# Сверка остатков WB, Ozon и склада — демо

Демо-версия сервиса для селлеров: остатки Wildberries, Ozon и собственного склада сводятся в одну таблицу, проблемные размеры подсвечиваются, рядом — рекомендации и макет уведомления в Telegram. Можно загрузить свои выгрузки (Excel или CSV) и увидеть расхождения на реальных данных.

Это статический сайт: сервера, базы данных и регистрации нет. Файлы пользователя читаются только в его браузере.

## Запуск

Нужен Node.js версии 22.23 или новее.

```bash
npm install        # один раз
npm run dev        # сайт для разработки: http://localhost:4321
```

Остальные команды:

| Команда | Что делает |
|---|---|
| `npm test` | Тесты логики: сверка, рекомендации, разбор файлов, симуляция |
| `npm run build` | Собирает готовый сайт в папку `dist/` |
| `npm run preview` | Показывает собранный сайт локально — так же, как он будет работать на хостинге |
| `npm run audit` | Проверяет зависимости на известные уязвимости |

Политика безопасности страницы (CSP) включается только в собранной версии, поэтому перед публикацией проверяйте сайт через `npm run build && npm run preview`, а не только через `npm run dev`.

## Настройки

Скопируйте `.env.example` в `.env` и заполните. Файл `.env` в репозиторий не попадает.

| Переменная | Зачем |
|---|---|
| `PUBLIC_CONTACT_URL` | Куда ведёт кнопка «Хочу так для своего магазина» в подвале: `https://t.me/…`, `mailto:…` или `tel:…`. Пока пусто — кнопка скрыта |
| `SITE_URL` | Полный адрес сайта, например `https://demo.example.ru` |
| `BASE_PATH` | Подпапка, если сайт живёт не в корне домена (например, `/sverka-ostatkov`). Для своего домена не нужна |

Секретов в проекте нет. Значения с префиксом `PUBLIC_` попадают в собранную страницу и видны всем — токены и пароли туда класть нельзя.

## Где менять тексты и контакты

| Что | Где |
|---|---|
| Контакт (кнопка в подвале) | `.env` → `PUBLIC_CONTACT_URL` |
| Заголовки, подписи, тексты кнопок, название вымышленного бренда | `src/content/site.ts` |
| Фразы рекомендаций, статусы в таблице, сообщения бота | `src/lib/messages.ts` |
| Демо-каталог и сценарий (какие позиции «проблемные») | `src/lib/demo-data.ts` |
| Пороги расчётов: «заканчивается за 5 дней», «3,5 часа в неделю» | `src/lib/config.ts` |
| Цвета и оформление | `src/styles/global.css` (переменные в начале файла) |

После правок запустите `npm test`: тесты проверяют в том числе сценарий демо (7 расхождений на старте, новые предупреждения в первые дни симуляции).

## Публикация

Сайт — это содержимое папки `dist/` после `npm run build`. Его можно положить на любой хостинг статических файлов.

### Хостинг в РФ (основной вариант)

1. Соберите сайт: заполните `.env` (`SITE_URL`, при необходимости `PUBLIC_CONTACT_URL`) и выполните `npm run build`.
2. Загрузите содержимое `dist/` на сервер или в хранилище российского провайдера (виртуальный сервер с nginx или объектное хранилище с раздачей статики).
3. Настройте веб-сервер по образцу `deploy/nginx.conf.example`: в нём уже есть перенаправление с http на https, HSTS и заголовки безопасности.
4. Проверьте результат: сайт открывается только по https, а в инструментах разработчика браузера (вкладка «Сеть») у страницы видны заголовки `Content-Security-Policy` и `Strict-Transport-Security`.

### GitHub Pages (быстрый вариант для показа)

Серверы GitHub находятся за пределами РФ. Для демо без сбора данных это допустимо, но если на сайте появится форма заявки — заявки нужно принимать и хранить в РФ (см. раздел «Если появится форма заявки»).

Сейчас сайт публикуется из ветки `gh-pages`, в которой лежит готовая сборка. Чтобы обновить опубликованную версию:

```bash
npm run deploy:pages
```

Команда соберёт сайт для адреса `https://<аккаунт>.github.io/sverka-ostatkov/` и отправит сборку в ветку `gh-pages`. GitHub обновит сайт через минуту-две. Ссылку для кнопки в подвале задайте в `.env` (`PUBLIC_CONTACT_URL`) перед запуском.

Можно перейти на автоматическую сборку при каждом обновлении `main`: образец лежит в `deploy/github-pages-workflow.yml.example`. Переложите его в `.github/workflows/deploy.yml` и выберите Settings → Pages → Source → GitHub Actions. Для отправки такого файла токену GitHub нужно право `workflow` (`gh auth refresh -s workflow`).

На GitHub Pages нельзя задать свои заголовки ответа. HTTPS и перенаправление с http там включены, политика CSP работает из `<meta>` страницы, но запрет встраивания сайта в чужие страницы (`frame-ancestors`, `X-Frame-Options`) действует только на своём сервере.

## Как устроен проект

```
src/
  content/site.ts     тексты и контакты
  pages/index.astro   единственная страница
  layouts/            общий каркас страницы
  components/         блоки страницы: шапка, вкладки, три экрана, подвал
  lib/                логика без привязки к странице (покрыта тестами)
    analysis.ts         поиск проблем и рекомендации
    messages.ts         тексты рекомендаций и сообщений бота
    demo-data.ts        демо-каталог
    demo-state.ts       симуляция продаж и счётчики
    tabular.ts          разбор CSV, поиск заголовков, угадывание колонок
    merge.ts            сведение файлов по артикулу и размеру
    csv.ts              выгрузка в CSV и файлы-примеры
  client/             код, работающий со страницей: отрисовка и обработка нажатий
  styles/global.css   оформление
public/vendor/        библиотека чтения Excel (SheetJS), лежит локально
tests/                тесты для src/lib
deploy/               пример nginx, образец автосборки, публикация на GitHub Pages
```

Правило разделения: всё, что считает, — в `src/lib` и не знает о странице; всё, что рисует, — в `src/client` и не содержит расчётов.

Единственная зависимость — Astro. Библиотека SheetJS лежит в `public/vendor/` файлом, а не ставится из npm: в реестре npm опубликована только её старая версия с известными уязвимостями. Обновить можно, скачав свежий `xlsx.full.min.js` с [cdn.sheetjs.com](https://cdn.sheetjs.com) и заменив файл.

## Безопасность

Что сделано:

- **Данные пользователя не покидают браузер.** Политика CSP содержит `connect-src 'none'` и `form-action 'none'`: страница технически не может отправить содержимое загруженных файлов по сети.
- **Защита от XSS.** Всё, что берётся из файлов пользователя, экранируется перед выводом (`esc` в `src/client/dom.ts`). В собранной странице нет встроенных скриптов и стилей; CSP разрешает только собственные файлы сайта.
- **Загрузка файлов.** Принимаются только `.xlsx`, `.xls`, `.csv`, `.txt`, `.tsv` размером до 20 МБ. Файлы не сохраняются и не исполняются — только читаются как таблицы.
- **Выгрузка CSV.** Ячейки, которые Excel мог бы выполнить как формулу, обезвреживаются.
- **Ошибки** показываются пользователю без технических подробностей.
- **Секреты.** В коде и в истории git нет ключей и паролей; `.env` исключён из репозитория.
- **Зависимости.** `npm audit` — 0 уязвимостей на момент сборки; проверка также входит в скрипт публикации на GitHub Pages.
- **HTTPS, HSTS, заголовки безопасности** настраиваются на веб-сервере — готовый образец в `deploy/nginx.conf.example`.

Что неприменимо, пока нет сервера: проверка данных на сервере, запросы к базе данных, CSRF, cookie сессий, CORS, хранение паролей, ограничение частоты запросов, капча. Сайт ничего не принимает от посетителя — ни форм, ни запросов.

### Если появится форма заявки

Форма потребует серверной части, и тогда перечисленное выше становится обязательным:

- сервер и база данных — в РФ; на сайте — согласие на обработку персональных данных и политика конфиденциальности;
- проверка всех полей на сервере, запросы к базе только с параметрами;
- скрытое поле-ловушка (honeypot) и ограничение частоты запросов; капча — Яндекс SmartCaptcha, если спам всё равно проходит;
- CSRF-токен, CORS только для своего домена;
- токены и пароли сервера — только в `.env` на сервере;
- в CSP заменить `connect-src 'none'` и `form-action 'none'` на адрес своего сервера — и убрать с экрана загрузки обещание, которое перестанет быть буквально верным для всей страницы, либо вынести форму на отдельную страницу.
